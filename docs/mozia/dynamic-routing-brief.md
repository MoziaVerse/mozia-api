# 平台动态路由策略简报

2026-09-14 · `codex/adaptive-supplier-routing`

**平台统一管理体验目标，用户只选择模型；先保障可用性，再根据性能分配流量，最后在达标资源中优化采购成本。客户售价不随选路改变。**

## 一次请求如何选择资源

1. **筛选资源**：模型能力、版本、权限满足要求。容量可不填写；填写了并发、RPM、TPM 上限，就必须遵守。
2. **先看可用性**：优先可靠的资源池；没有正常池时使用可用性下降的备用池。故障或过载冷却期间暂停派发。
3. **再看性能**：同一可用性层内，达标池默认获得 90% 的常规流量；偏慢或缺少性能样本的池共享 10%。不会仅因为速度慢就停止分配流量。
4. **达标资源优化成本**：达标自部署优先。第三方按预估采购成本逆平方分流，例如成本 1:2，流量约 80%:20%。
5. **全部偏慢仍继续服务**：更接近性能目标、达标比例更高的池获得更多流量；每个池保留正权重。此时性能优先于低价或自部署身份。
6. **失败回退**：按原有重试次数、请求总时限和故障域规则切换。已经输出的流式内容不会拼接另一家响应。

## 初始参数

| 项目 | 默认行为 |
|---|---|
| 可用性门槛 | 成功率至少 95%，429 另行统计；这是路由门槛，不是对外 SLA |
| 性能目标 | 流式首 Token 不超过 5 秒，有效吞吐至少 10 tokens/s；每项至少 90% 有效请求达标 |
| 谁设置目标 | 平台管理员按模型校准，同一规则下所有候选供应商使用同一标准 |
| 观察窗口 | 优先最近五分钟；低流量时最多向前累计一小时；实时排行榜仍显示五分钟 |
| 样本数量 | 可用性和性能分别至少 20 个有效样本，性能数据缺失不阻止可用性成熟 |
| 新池和故障恢复 | 共享约 5% 试运行预算，每池最多 1 个试运行并发；全部新池时在并发保护下启动 |
| 明确故障 | 连续 3 次，或样本足够后失败率达到 20%，默认冷却 30 秒 |
| 过载 429 | 独立从 1 秒起指数退避，默认上限 30 秒；尊重 Retry-After，最多一天 |

90%/10% 是**组间配比**，不是每家供应商固定份额，也不是速度的综合评分。存在试运行流量时，该配比作用于剩余常规流量；没有另一组候选时，由现有组承接全部常规流量。容量、并发、候选变化和重试会影响实际比例。

## 本次改进

- 将可用性下降与性能偏慢分开；慢服务保留流量。
- 从均值门槛调整为请求达标率，减少均值掩盖尾部慢请求的问题。
- 修复低流量资源难以积累样本、单次 429 退避过重的问题。
- 管理页面分别配置可用性和性能，显示达标率、状态及最近一次选路依据。
- 保留原有资源池、渠道、可选容量、报价快照、重试和客户计费机制。

测试重点包括：慢自部署与快第三方 10:90、全部偏慢时性能优先、可靠慢服务优先于不可靠快服务、均值达标但慢请求过多、低流量/过期样本、429 退避以及原有计费和容量回归。最终测试与部署结果见交付说明。
